# 07 · 不可越级开发路线与验收门槛

> **原则：先完成可验证闭环，再扩展模拟广度。每个阶段结束都必须存 Git 稳定标签，并通过对应 Gate；没过门禁就不能声称升级成功。**
>
> V0.1、V0.2 是连续开发阶段；**不建议将缺少完整存档的 V0.1 当作正式可长期游玩的版本发布**。

## 固定依赖链

```text
G0 规范/测试骨架
  ↓
V0.1 基础互动闭环 -> G1
  ↓
V0.2 世界永久存档 -> G2【第一个可长期玩的版本】
  ↓
V0.3 生存/搜索/时间/天气资源 -> G3
  ↓
V0.4 NPC 人格/关系/自治 -> G4
  ↓
V0.5 战斗/制造/基地/车辆 -> G5
  ↓
V0.6 阵营/地图/世界演化 -> G6
  ↓
V1.0 全面回归/性能/可访问性/发布 -> G7
```

## G0 · 工程基线（开始编码前）

交付：Git 仓库、README、AGENTS、本计划、TypeScript 工程与 Core/UI/Storage/AI 接口骨架、测试框架、CI 基本检查、首个确定性状态测试。

验收：运行测试框架通过；能够用固定种子构建 WorldState；核对状态不变量；`PROJECT_STATE.json` 真实记录。

禁止：在架构底座没确定前并行堆砌庞大地图、NPC 任务、AI 插画。

## V0.1 · 基础互动闭环（G1）

范围：新游戏/角色基础创建、单个居民楼场景、沉浸文字输出、动态行动按钮、自由文本动作、最小动作集合（观察、移动、检查、搜索、拾取）、统一时钟与基础状态条。AI 意图解析走 adapter；没有模型时可用按钮和模板退化运行。

验收：
- `观察门缝` 能在同一场景产生“看到多少”和“是否暴露”的独立判定，并且信息不剧透；
- 菜单以外的文本输入能识别到原语，无法执行时明确报告，不伪造后果；
- 场景物品取走后不会在当前会话内重复出现；
- 20 次顺序行动的状态不变量、时间消耗、物品权属均通过测试；
- 无权直接写世界状态的 UI 和 AI 层有测试证据。

**局限**：这一阶段可用于交互试验，不满足长期存档要求。

## V0.2 · 永久存档（G2）

范围：多槽存档、自动存档、手动存档、读档、导入/导出、世界记忆日志、版本化 schema、损坏检测、回退测试。

验收：
- 完成“观察→搜索→拾取→遇见 NPC→关系变化→保存→关闭→读取”，世界事实逐项一致；
- 写入中断模拟不产生半存档，旧档仍能恢复；
- 同一个存档恢复后，已搜刮的物品不重新出现；
- 至少 3 个独立存档槽能互不串档；
- 保存成功或失败都给玩家真实反馈。

**第一个适合普通玩家持续游玩的里程碑。**

## V0.3 · 完整生存环（G3）

范围：饥饿/口渴/疲劳/伤势/感染/体温/负重，有限物资、详细搜索、天气、昼夜、移动耗时，疾病/死亡基础因果，难度配置。

验收：
- 连续缺水、睡眠不足、低温等状态按逐步机制恶化，不瞬间无因死亡；
- 天气确实影响观测/行动/体温等数值；
- 资源消耗守恒、时间正确推进、存档一致；
- 至少 3 种极端边界测试（0 体力、超负重、无水）通过。

## V0.4 · NPC 自治与关系（G4）

范围：重要 NPC 档案、信任/敌意/恐惧、目标/记忆、行为调度、对话/交易/拒绝/谎言，NPC 的知识隔离。

验收：
- NPC 在没有玩家直接命令时完成可追溯的行动；
- NPC 被玩家救助/欺骗后的后续行为符合记录事实，不会凭空遗忘；
- NPC 对不知道的玩家行为不能“全知”；
- 至少一个 NPC 会拒绝不符合利益的玩家请求。

## V0.5 · 深度生存系统（G5）

范围：危险战斗、武器/弹药/噪音、制造、基地设施、车辆检查与维护、长耗时可中断任务。

验收：
- 武器消耗、受伤、噪音引发的 NPC 反应有可追溯事件链；
- 造物、维修扣除材料与时间，失败/中断也遵循约束；
- 基地设施与车辆状态能被保存，不能重新加载就自动满油或满耐久；
- 死亡流程有合理原因和最终回顾。

## V0.6 · 扩展世界（G6）

范围：多区域地图、阵营利益/冲突、区域事件调度、营地变化、资源流通、天气与灾害扩展；可选离线补算（必须用户显式开启）。

验收：
- 玩家在 A 区时，B 区可按照简化规则发生合理变化；
- 阵营与营地变化由库存/行动/事件解释，而非只靠文案；
- 区域切换、保存、读取以后实体和事件无重复；
- 离线模式关闭时暂停；开启时按明确上限补算，能预览并保存结果。

## V1.0 · 可交付版本（G7）

范围：内容深度、交互打磨、文本质量、语音输入适配（视平台可用性）、移动端适配、性能、故障恢复、帮助/设置、导出迁移。

验收：
- 全部核心 P0 场景回归通过，跨版本旧存档迁移无数据丢失；
- 从建角到死亡或存档恢复形成完整游戏闭环；
- UI 文本/按钮/自由输入均能操作，不存在只能靠固定选项推进的关键剧情；
- 性能和崩溃门槛按实际测试设备记录并达成，不凭空声称已达标。

## 所有 Gate 通用门槛

1. 本阶段范围完整并有可复现演示。
2. 自动测试全绿；存在已知缺陷时写明是否阻塞，不得以“主要通过”偷换。
3. 所有状态持久化与新增字段具有兼容方案。
4. Git 有可恢复标签/提交；能说明回滚方案。
5. 更新 `PROJECT_STATE.json`、`docs/10_SESSION_HANDOFF.md`；涉及重大设计变化需 ADR 记录批准。
6. 必须由用户显式授权进入下一大阶段；Codex 不得因“还有时间”擅自提前开发。

## 允许的并行开发边界

同一阶段可以将测试、UI、内容与纯 Core 模块并行，但同一数据协议必须指定唯一负责人；合同先冻结，再并行实现。任何相互冲突的接口变更先回到 ADR，不得由 Agent 私自统一为新规则。
