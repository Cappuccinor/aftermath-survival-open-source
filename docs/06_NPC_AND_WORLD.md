# 06 · NPC、事件与世界自主运转

## NPC 最小自治模型

每个重要 NPC 有：`need`（即时需求）、`goal`（长期目标）、`memory`（事件证据）、`relationship`（与各人关系）、`riskTolerance`（风险承受）、`schedule`（行动计划）、`location`（位置）、`resources`（资产）、`status`（身体/心理）。

在每个调度周期：

1. 读取 NPC 能知道的事实（不能直接窥视世界秘密）。
2. 按需求、目标、关系、当前环境形成候选行动。
3. 用同一个命令网关进行规则校验与结算。
4. 更新 NPC / 世界状态、日志和玩家的可见线索。

NPC 台词可以由 AI 写；动机、目标、是否成功、真实库存、对玩家的记忆不能由 AI 随意改变。

## 世界推进范围

- **玩家在游戏中时**：统一 GameClock 推进，NPC 的离屏行为和事件按调度器结算；无需把每名遥远 NPC 每秒模拟一遍，允许按区域简化。
- **玩家退出后**：默认 GameClock 暂停并完整保存。
- **可选离线补算**：明确开启后，按经过的现实时间换算、设上限、预览重大事件；只走可复现调度和原子存档流程。无后台服务器不宣称实时持续运行。

## 事件频率与因果

- 事件按区域危险度、时间段、天气、先前行为、资源压力生成；定义冷却与冲突条件。
- “玩家开枪”可触发 `NoiseEmitted`，随后附近 NPC 根据听力/距离/遮挡更新调查意图，不是立即凭空刷怪。
- “玩家偷食物”要有 `ItemTransferred` 和可能的 `TheftEvidence`，营地成员只有调查得到证据后才可能怀疑。
- NPC 不应掌握玩家隐藏的所有行动；关系变化可依据被观察、传闻或可信证据。
- 事件可以发生在玩家视野之外，但玩家只能通过结果、目击、声音、传闻等渠道获知。

## 阵营与基地扩展

- 阵营以库存、人员、据点、政策、对外关系、目标为核心，而非只用“好/坏阵营”标签。
- 基地建设消耗物品与时间，设施具有耐久、维护成本、正负效果。
- 地图物资总量有限，资源刷新须遵守合理来源（外来补给、采集/种植、交易、制作）。
- 车辆、基地与 NPC 任务都通过调度器触发 `JobCompleted/Failed`，并能被世界事件中断。

## 性能伸缩

V0.4 先实现 1—3 个重要 NPC 的自治小范围场景；V0.6 再将调度扩展到区域/阵营，避免最初就创建无法测试的数千名全精度 NPC。
